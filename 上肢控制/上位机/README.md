# CyberArm 双关节控制 v2.3.3：静默启动最新后台

每次双击 `run.bat` 都重新启动本地源码对应的后台，不再直接复用已运行实例。新版实例通过带本地私有令牌的退出接口正常断开 CAN、退出并释放端口；历史版本仅在端口进程、脚本和双机身份匹配、API 已确认断开后才退出。启动器用单独互斥锁串行处理重复启动，退出过程拒绝新的连接/运动请求。

关闭网页本身不代表后台退出；再次启动时自动处理残留实例。Windows 关闭后台控制台时也会尝试停止双机并释放串口。运动或保持中的后台不自动替换，身份不明、通信异常或断开失败时不强杀；不会自动连接或恢复运动。界面不增加更新提示，移除旧版重启横幅；启动失败仅记入 `tmp/backend_startup.log`。

数字孪生界面把负载承托与空载重力补偿合并到“运控模式参数调节”。支持原 PD、跟随承托、静态补偿三种选择，直接编辑 Kp/Kd/Ki、附加补偿上限、变化率、死区和学习窗口。仅跟随承托使用面板中的 Kp/Kd；原 PD 与静态补偿仍使用两关节各自的增益。

页面读取现有配置，不套用预设覆盖自定义参数；刷新保留未保存草稿，撤销只恢复已保存参数。停止后明确保存，下次手动启动才生效；关闭负载补偿保留其参数。空载模型系数、标定数据、零点、限位、默认速度 0.3 rad/s 和默认转矩 3.5 Nm 都不因模式参数保存而改变。重力补偿仍独立标定/开关，可与负载补偿叠加；不自动开启未标定的补偿，也不包含人臂模型。再次运行启动器会加载新版接口。

v2.3.1 按用户要求取消运动中“实际速度超过 `maximum_speed_rad_s×1.5+0.05` 就停止双机”的独立判断（当前配置原阈值为 0.5 rad/s），不新增替代速度停机逻辑。设定/轨迹速度上限仍为 0.3 rad/s，启动静止检查、到位稳定判定及其他保护不变。**设定速度上限并不保证实际速度不会超过它；取消此判断后，软件不再单独拦截真实超速，不能据此直接穿戴试验。** 改动需重启后台生效，既有锁存不自动复位，也不自动运动。

本地网页同时显示肩关节和肘关节的真实反馈、目标角度、运行参数和历史曲线。服务只监听 `127.0.0.1:8765`。

桌面工作台按“左曲线 / 中模型 / 右操作”排列。右侧直接调两关节目标并点击控制；速度、力矩、零点与限位在“运动设置 / 零点”中，详细数据在“出力诊断”中，补偿参数单独折叠。双关节控制与顶部停止按钮不随参数区滚动隐藏。输入角度和拖动模型只更新目标值，不会改变模型实际姿态或自动驱动电机；窄屏自动重排。

## 启动

双击 `run.bat` 启动数字孪生界面；双击 `run_classic.bat` 启动 Tk 经典界面。两者共用一台 CANable 和 `classic_dual_config.json`，因此一次只运行并连接其中一个上位机。

## 数据集记录与输出

连接后，在孪生中间栏“数据集”或经典版“数据集输出”页点击“开始记录 → 结束记录 → 下载/导出 ZIP”。开始或结束记录都不发电机控制命令。四张 CSV 分别保存逐帧反馈、成功发送的周期命令/估算、异步参数读回、事件；附 UTC 时间戳、Unix 纳秒、单调时钟/相对秒、关节身份、字段字典、配置与代码版本快照、完整性标记及 SHA-256。使用通用 CSV＋JSON 结构，不冒称某一专用机器人数据集标准。

文件持久保存在 `datasets/<session_id>/`，不会覆盖或自动删除旧记录。反馈没有到来时不补样、不补零；参数不会被伪装成与反馈同步。记录器独立写盘，队列满/写入失败仅结束记录并标不完整，不改变运动控制；断开连接自动结束记录，异常退出可能保留未完成数据。关闭网页不结束后台采集。当前网页须重启新版后台后才能使用记录接口；不自动接管或操作实机。

完整字段、时间和分析约定见 [DATASET_FORMAT.md](DATASET_FORMAT.md)，可用 `tools/validate_dataset.py` 验证目录或 ZIP。

## 电机与安全门槛

| 关节 | CAN ID | MCU UID |
|---|---:|---|
| 肘 / 小臂 | 127 | `034C3B8A2093B015` |
| 肩 / 大臂 | 126 | `3A4B3B8A2093B015` |

连接时读取两台电机的 UID。任一身份未验证、软件零点未采集、方向和限位未确认、关节未验收或存在故障时，界面不会启动该关节。首次运动前停止双机，最多等待 3 秒：每 0.1 秒重复普通停止请求刷新反馈（不使能、不清故障），在最近 0.55 秒窗口内，两关节各至少 4 帧、采样跨度至少 0.4 秒，有符号平均速度绝对值不超过 0.03 rad/s，且编码器角度总波动不超过 0.1°才通过；任何样本速度超过 0.15 rad/s、相邻反馈间隔超过 0.25 秒、缺少新样本或真实位置持续漂移都不能通过。平均速度处理零中心速度估算噪声，独立编码器范围约束防止真实往复运动被正负平均掩盖。这是保留的启动静止检查，不是已取消的运动中实际超速停机判断。超时显示具体关节、原始/多帧速度、角度波动或缺反馈原因，拒绝使能；需先支撑机构，不能从下落状态启动。检查通过后再写入运控模式和力矩上限，并独立读回核对。所有待使能关节都通过后，才允许使能其中任何一台。读回超时或不一致会拒绝启动，不会退回未核验控制。

持续位置控制：给定角度后按原速度/加速度规划运动，轨迹结束后持续发送最终位置、零目标速度及已明确开启的补偿，直到人工停止、换目标或触发保留的保护。“已到位”仅是显示指标（误差不超过 1.5°、连续编码器/速度窗口稳定并持续 0.5 秒），不切换控制方式、不限制换目标、不触发到位或恢复超时停机；轻微抖动、偏离目标时仍继续控制。当前规划轨迹结束后可直接换目标，无需等待实际到位，沿旧参考终点重新规划并保留补偿，避免因重新对齐实际位置而瞬间卸掉 PD 支撑。规划尚在执行时暂不支持中途换目标。

力矩上限、速度/加速度规划、补偿参数及防积分饱和均不变；堵转、失联、故障、温度、角度、电压和反馈力矩等保护仍保留。高力矩、低速且误差超过 3° 持续 2 秒仍会按现有堵转逻辑停止，故“持续控制”不代表无条件抵抗任意负载。旧配置的 `hold_error_deg` / `hold_error_timeout_s` / `convergence_timeout_s` 兼容忽略，不改写用户配置。修改需重启后台生效，不自动重启、复位已有锁存或试动。详见 [版本变更与验证](VERSION_NOTES.md)。

启动参数核验在原有每项 0.8 秒时限内，每 0.2 秒重发一次只读请求以应对单次丢帧；不重写、不使能、不延长核验期限，也不使用启动前缓存的值。持续不回复或回复值不符仍拒绝使能。

**停止、退出、断电或保护动作可能释放支撑力并导致机械臂下落。必须先有机械支撑/防坠及实体急停，不能靠电脑控制保证失联/断电安全；当前版本只用于无人佩戴的空载调试。不要把关闭浏览器页面当作停止电机。**

两台电机有各自的方向、零点、软限位、速度上限、转矩上限和 PD 参数。当前肘关节软限位为 `0°～90°`；两关节默认目标均为 `0°`、默认速度为 `0.30 rad/s`、默认转矩限制为 `3.5 Nm`，软件允许的转矩限制上限为 `5.0 Nm`。这些默认值不使电机自动运动；改动安全参数后须重新确认并启用。首次实机试运行仍应手动调低速度和转矩，并按实际机构、电源与负载选择尽可能低的限制。`exoskeleton_config.json` 是旧单电机配置，数字孪生 v2.0 不再读取它；历史零点仅保存在新配置的候选字段中，不会自动启用。

## 首次使用

1. 确认机构固定或空载、无人穿戴、路径清空、电源限流合适且实体急停可用。
2. 在页面选择 CANable 串口，连接并确认两台 UID 都通过验证。
3. 若页面提示缺少零点，分别把肩、肘关节置于各自参考姿态，点击“当前位置设为零点”。已有零点可跳过。
4. 核对两关节实际正方向、机械空间及安全范围，点击“确认并启用双关节”；弹窗会列出本次要保存的限位和控制参数。高级设置默认收起，修改后需重新确认。
5. 先做小幅、低速的单关节动作，观察方向、反馈和急停；再使用双关节协调运动。

三维实体臂只跟随类型 2 CAN 实际角度反馈；独立的浅黄色透明线框臂显示目标预览，可拖动其大臂/前臂设定目标。两者互不覆盖：输入、滑杆或拖动只改变透明臂和目标数值，不改变实体实际姿态；点击控制并确认后才发送运动指令。页面约每 100 ms 读取一次状态，请求不重叠；运动、持续控制、停止或锁存都不会冻结实体臂显示，只要有新鲜反馈就更新。拖动空白处只旋转视角。

超过 0.3 秒没有新鲜反馈时，模型冻结在最后已知姿态并变暗、明确显示“非实时 / 反馈过期”，角度卡片显示 `--`，模型下方旧角度标注“旧”；从未收到完整有效姿态时不伪造零度模型。断开或网页请求失败也不把缓存标为实时。此项仅改变显示，不新增 CAN 采样/使能指令；电机停止后若不继续回传反馈，页面会显示过期，而不是猜测当前位置。协调运动仍按原速度、加速度限制规划五次曲线。

## 空载重力补偿：首次标定

补偿默认关闭，连接、标定或保存设置都不会自动使能/运动。参数来自本项目 CAD 安装孔与单件实体重心，以及用户提供的质量：小臂 73.64 g、大臂 103.92 g、肩连接件 80.68 g，每台电机按 317 g 估算。肩肘轴距 299.156 mm；模型上界肩约 1.455 N·m、肘约 0.0559 N·m。未包含人臂、遗漏支架/螺钉/线束、摩擦和惯性。打印填充导致的质量分布偏移、实际电机安装偏心需要进一步标定。

1. 先支撑机构并停止双机，保证无人佩戴。核实两根抬臂轴平行且水平；倾斜/其他装配不能套用当前平面模型。
2. 在数字孪生的“空载重力补偿 → 首次标定”，或经典版的“空载补偿标定”页，输入当前两段臂各自相对水平的物理绝对角度。按同一固定观察侧，水平向右 0°、竖直向上 +90°、向下 -90°；不是软件显示角，也不是肘部相对角。不要猜测或直接填写目标角度。
3. 核对软件角增大时的物理方向：肩部角度及肘部相对角的逆时针取 +1，顺时针取 -1。确认后，程序在停止后的新反馈上计算偏置，保存标定，但仍保持电机停止。
4. 下次手动点击“双关节运动并保持”时才平滑加入补偿，默认渐入时间 1 秒。补偿是随真实角度变化的值，不是恒定 1.45 N·m。开启补偿后必须使用双关节按钮，另一关节可将目标设为当前角度，不会暗中使能未选中的电机。
5. 采新零点或修改任一软件方向会关闭补偿、使标定失效，必须重新标定。

模型定义：`theta_s = sign_s*q_s + offset_s`，`theta_f = theta_s + sign_e*q_e + offset_e`。
软件坐标补偿为 `tau_s = sign_s*(1.39872366*cos(theta_s)+0.05592679*cos(theta_f))`、`tau_e = sign_e*0.05592679*cos(theta_f)`，角度计算用弧度，再按软件到电机的方向系数变换。保持运动状态下不能直接切换补偿设置。

## 换目标与诊断

- 当前规划轨迹结束后接受新目标，无需等待实际到位或稳定；从旧参考终点重规划，不瞬间消除负载下的 PD 支撑；未修改的已使能关节保留原目标。规划尚在执行时拒绝重复启动，停止按钮始终有效。首次启动仍需确认；已有控制过程内点击换目标不重复弹窗，拖模型仍然只改目标值。
- 保持中新增使能关节、更改 PD 或力矩上限，需要先支撑并停止双机。原配置 Kp=3、Kd=1 保持不变；明确启用承托档后，下次手动启动采用档位中的 Kp=12、Kd=1.5，见下节。API 明确提供本次 PD 参数时，以该参数为准，保持中仍禁止修改。
- 每个关节显示实际目标误差、补偿指令（电机坐标）、未限幅 PD+补偿估算，以及模式、力矩上限、Iq、电压和电流上限读回。**估算不是实测输出，反馈力矩也不是独立测力传感器值。**
- `limit_cur` 是说明书的位置/速度模式电流上限，不将它误当运控模式的总输出限制，也不会自动把电流上限写大。Iq/电压不支持时显示未读到/过期，不补零伪造数据。
- 参数响应只有类型、地址、索引、保留/状态字段、数值范围与待处理请求全部匹配才接收；关键模式/力矩上限运行中读回不一致或连续 3 秒无有效读回会停止。
- 电机侧 `limit_torque` 读回核对后负责 PD+前馈的总输出上限，前馈还单独限幅；不能仅凭读回认定固件物理限幅已实测验证。反馈持续超过限制还会触发保护。独立电源限流和实体急停仍然必需。
- `/api/history` 额外提供 target、error、gravity、estimated_torque、iq、vbus 的内存滚动记录。重启后不保留这些运行记录。

## 更新与离线验证

### 负载承托档（试验，必须手动开启）

旧版 Kp=3 在静态误差 5° 时仅要求约 0.262 Nm，调大力矩上限并不会让它主动要求更多。新档位采用 Kp=12、Kd=1.5，相同位置误差的比例出力提高四倍，并以 Ki=2 Nm/(rad·s) 逐步补足负载所需支撑。它仍是运控模式 0：电机执行 PD，主机只把重力前馈加积分校正放入 Type1 力矩字段，**不把主机估算的 PD 再叠加发送**。

在数字孪生的“负载承托控制”或经典版补偿页，先支撑、停止双机，再点击“启用/升级负载承托档”并确认。此操作只保存设置，不连接或使能电机。下一次手动启动才生效；关闭后恢复原关节 PD 配置。开启状态会保存，重启后首次运动确认仍提示档位。保留已有 UID、方向、零点和限位。旧版已开启的补偿不会自动升级、更不会自动提高 PD；需明确选择新档。

承托档使用轨迹**当前设定位置**与真实位置的误差，而不是一开始就积分最终目标的全程误差。在运动中及保持时，误差在 0.2°～15°、编码器拟合的跟踪误差变化率不超过 0.12 rad/s 才积累；短窗口、缺反馈、采样间断、快速受推或往复摆动时冻结。最多附加 ±2.5 Nm（还受本次总力矩限制约束）、变化率最多 0.4 Nm/s。PD+重力+积分估算接近饱和时拒绝继续向饱和方向累积，允许反向卸载。换目标保留已有支撑，再由新轨迹误差平滑调整；停止、断连或故障清零，学习力矩不落盘。到位超时和其他硬保护不延长、不取消。

下发诊断显示成功发送的实际量化 Kp/Kd、前馈力矩字段、本次总上限、编码器反馈采样时间及对应的 PD/总出力估算；字段带发送时间/年龄。停止后清空，旧反馈不作为当前出力证据。发送成功不代表电机已经执行，力矩估算不是实测，更不能仅凭参数读回断言固件实际限幅正确。实际反馈力矩、Iq 和电压另列，未读到不补零。

这些档位参数是待实机验证的试验起点，不是已辨识的机械模型。持续静止外力仍可能被当作负载；本功能不是人体意图识别，不适合直接穿戴试验。原 CAD 补偿仍关闭，未自动重新启用；软件不会提高总力矩上限、电压或电流参数。如果新鲜指令估算已充分要求出力但真实输出仍上不去，需要再检查实际参数、供电和反馈，不能继续盲加积分。

旧进程不会自动加载新的 Python 控制代码。先支撑机构、手动停止并断开，退出旧上位机后再启动；仅刷新网页不等于更新后端。新版网页检测到旧版服务时禁止新运动，但保留停止入口。禁止两个上位机同时连接 CANable。

本次保留既有 UID、软件零点、肘限位 0～90°、默认速度 0.3 rad/s、默认力矩上限 3.5 N·m 和最大力矩 5 N·m。把旧保存的最大速度 0.5 修正为程序支持的 0.3，避免启动校验失败。

离线测试通过假通信链路运行，绝不打开串口：设置项目 `.deps` 为 Python 搜索路径后，运行 `python -m unittest discover -s tests -v`。覆盖到位保持、补偿与方向、关键参数读回失败禁止使能、堵转、超温/越界和断反馈停止，以及保持偏差单独超过旧阈值不再停机、扰动恢复和既有到位超时仍有效、实际速度单独越线不再停机、设定速度上限仍有效等。`tools/preview_hold_ui.py` 是只读合成界面验收工具：没有串口连接能力，全部 POST 被拒绝，不可用于实机控制。

## 文件

- `digital_twin_server.py`：本地 HTTP 服务和双机连接管理。
- `classic_dual_controller.py`：经典版与数字孪生共用的双电机安全控制核心。
- `classic_dual_config.json`：两关节身份与安全配置。
- `web/index.html`、`web/styles.css`、`web/app.js`：三维模型、操作界面和曲线。
- `cybergear_protocol.py`：CyberGear CAN 帧封包与解析。
- `motion_policy.py`：纯计算的空载补偿模型、标定绑定与保持保护参数。
# 手臂与手部统一入口

双击本目录 `run.bat`，浏览器打开本机 `http://127.0.0.1:8765/`。页头分别显示手臂和手部的在线状态，点击“手臂”或“手部”切换操作区，可只连接其中一端。

手臂使用原有 CANable 串口连接与肩肘控制流程。手部先把电脑 Wi-Fi 接入 Hand-Exo，再点击“连接手部”。四指的阈值与速度来自板上现有配置。输入各通道闭合百分比后点击“发送四指姿态”，或使用逐指抓握、停止并保持、关闭驱动按钮。

手部“断开通信”会停止状态监测，已启用的驱动继续按板上策略运行。其他页面持有控制权时，上位机显示状态并禁用手部控制；回到原控制页面操作。启用手部驱动后，应在核对反馈并关闭驱动后再重启本机后台，以保留控制身份。

Clash TUN 使用现有 192.168.4.0/24 排除项。上位机请求绕过系统 HTTP 代理，网络仍需能够直达控制板。当前数据集按钮继续记录手臂数据。

离线验证可运行 `python -m unittest discover -s tests`（使用本目录 .deps 中的依赖），以及 `node tests/test_hand_web.cjs`。后者使用本机 Edge 和工作区已有 Playwright，通过模拟接口运行完整页面。

# 四指外骨骼控制台 v2

本项目使用微雪 Servo Driver with ESP32 控制板和四个 SC09 舵机。网页由 ESP32 自己提供，手机、平板和电脑连接控制板热点后访问同一地址。3D 模型、图表和脚本都包含在固件资源中。

## 已实现功能

- 从原项目总装 3MF 提取 32 个零件实例，显示四指及支撑结构，拖动指部或滑块可编辑目标姿态。实心模型对应舵机反馈推算，透明模型对应目标。
- 每指一个驱动自由度。指节模型使用近似耦合铰链映射，尚未求解原八连杆闭链运动学。显示的指节姿态需要进一步通过实机角度标定。
- 目标预览、执行目标、开启拖动同步控制。默认拖动仅预览，勾选同步后连续发送目标。
- 手指页可统一设置四指速度上限（20～500 编码步/秒），配置页可逐指设置；保存到 NVS，断电保留。运动中先停止并保持再调速，调速本身不会启用或移动舵机。
- 保存最多 16 个自定义手势，重名覆盖。真实设备将手势写入 NVS，断电保留。选择手势可以预览、执行或删除。
- 四指逐步闭合，分别读取最新负载。负载先做中值滤波，再联合持续性与位置进展确认遇阻，确认后锁定当前位置；负载回落也不自动继续推进，其余手指继续。四指均遇阻或到达行程终点后结束抓握，位置继续保持。新的抓握或目标姿态命令可以重新开始推进。
- 显示四指在线状态、位置、负载、速度读数、电压和温度。图表可切换这些量，保留最近 30 秒。
- 停止并保持、关闭舵机驱动、反馈失联处理。网页断连不自动关闭驱动。抓握和 UART 反馈运行于独立任务，静态网页下载不阻塞控制循环。UART 访问及状态变更由互斥锁串行保护。
- 单终端控制权及动作版本号，停止或释放后拒绝排队中的旧运动请求。

## 板载 OLED 和单舵机改号

OLED 使用原板的 SSD1306 128×32，SDA 为 GPIO21，SCL 为 GPIO22，默认地址 0x3C，同时兼容 0x3D。使用 ESP32 自带 Wire，无需安装显示库。启动显示 IP，运行时四行分别显示 IP、配置的舵机 ID 与状态、在线数量与最低反馈电压、运行状态或最近改号结果。每 800 ms 刷新一次。ID 后的 + 表示反馈在线，- 表示无新反馈，! 表示报警，? 表示模式读取异常。AP 数字为热点连接的终端数量。

在网页“配置”中使用“搜索 ID（1～20）”查看总线响应，再填写原 ID、新 ID 并点击“写入新 ID”。出厂原 ID 为 1。修改时仅连接一只舵机，设置后断电更换下一只。搜索 ID 的个数不能用来识别具有相同 ID 的多只舵机。

固件会检查目标是否占用、解锁 EEPROM、写入编号，并回读新 ID、锁定状态及旧 ID 是否仍有应答。界面和 OLED 会报告结果。改号不会自动重排四指配置，全部改好后核对下表对应关系和行程。控制启用时不允许改号或搜索。

如果写入时通信中断，应先重新搜索实际 ID，再决定是否重试。新 ID 已响应而锁定未确认时，界面会明确提示检查结果。

## 默认四指配置

| 手指 | 默认 ID | 张开位置 | 闭合位置 |
|---|---:|---:|---:|
| 食指 | 1 | 250 | 600 |
| 中指 | 2 | 150 | 650 |
| 无名指 | 3 | 800 | 300 |
| 小指 | 4 | 600 | 200 |

默认 ID 对齐用户提供的修改版中 1、2、3、4 的回退列表，行程初值来自原机械项目，需逐指核对。设备已保存的配置优先于默认值。首次使用在配置页填写实际参数并保存，设置为已核对。该页同时设置逐指负载阈值，默认 300。负载使用 SC09 原始反馈读数，指尖力需要标定。位置使用编码值 0–1023。速度读数保留库的原始单位。

速度初值仍为 100。控制步进按每指两次指令之间的实际间隔计算，避免轮询导致额外降速；两次推进至少间隔 40 ms，计算时最多计入 80 ms，目标姿态每次最多推进 40 编码步，抓握最多 12 编码步。因此设置值是速度上限，抓握还受反馈频率和小步进上限约束，不能直接等同实测运动速度。

### 滤波与位置联合判定

普通目标移动和逐指抓握都保留遇阻保护。每指对完整有效反馈的负载绝对值做 3 点中值滤波；最近 5 个滤波结果至少 3 个达到该指原有阈值、当前滤波值仍达阈，并且这些结果的时间跨度至少 120 ms，才形成持续高负载证据。同时要求已下发的目标仍在运动方向前方、位置在至少 160 ms 内未累计向目标前进 3 编码步；低速时这个窗口按 max(160,6000/speed) ms 加长，例如速度 20 时为 300 ms。以上同时成立才锁定当前位置。达到目标的 3 步容差时优先正常完成动作。

确认期间沿用原来的小步推进，不提前发送当前位置保持来卸载。确认后进入 Contact，负载回落也不恢复运动；明确的新动作才重新开始。连续同方向的拖动目标不会反复清空判定历史；方向改变、新抓握、停止或反馈读取失败会清理相应历史。严重过载仍直接使用原始负载立即检查，不等待滤波，报警、温度、反馈丢失及行程保护保留。阈值、速度、Config 结构与 NVS 保存格式没有因滤波修改。这些时间与位移常量是初始实现参数，尚需实机接触测试标定。

状态 contactFilter=1 表示支持本次逻辑。各指新增 contactRawLoad、contactFilteredLoad、contactVotes、contactNoProgressMs、contactPositionError、commandedP、contactSampleMs，记录最近一次运动判定的原始负载、滤波值、达阈票数、无有效进展时长、沿运动方向的指令位置误差、实际下发目标及板内采样时刻。动作结束后这些字段保留最后一次判定记录，当前实时负载仍是 load；停止或新动作会清理记录。tools/record_session.py 同步记录这些字段且继续排除访问凭据。

按用户要求，取消网页断连后自动关闭驱动；最新固件返回 disconnectRelease=0、leaseMs=0。网页每 600 ms 尝试发送心跳，切到后台也不主动停止；浏览器可能降低后台计时频率，但不会因此关闭驱动。已接受的运动仍会执行到目标，保持时继续保持；舵机反馈丢失、报警、过温、严重负载超限、越界以及抓握 20 秒超时保护仍保留。新网页读取固件字段显示真实策略，连接旧固件时仍提示其 3 秒保护。关闭舵机驱动只停止主动输出，齿轮与连杆不会因此解锁，不能等同于张开手指。启用期间保留原终端控制权；新页面可先停止，再关闭驱动并重新启用。驱动已关闭时，空闲控制权 3 秒后清理。状态接口保留 heartbeatAgeMs 供诊断，设定速度为各指 speedSet，speed 仍是反馈速度。

读取兼容性修正后，位置、速度、负载、电压、温度读取范围为地址 56～63，通信超时为 20 ms。模式寄存器读取失败单独显示，舵机报警与通信失败分别记录。报警状态或模式未知时保持禁止启用控制。状态接口增加 alarm、readError、failures 和 mode 字段。这些固件改动需要重新编译上传，并使用项目同目录的 SCServo 库。

## 本地预览

双击 preview.bat，或在当前目录运行：

~~~powershell
python preview.py
~~~

打开 http://127.0.0.1:8766/?demo=1 。演示功能使用模拟反馈，手势保存在本浏览器。手机预览运行 python preview.py --lan，在同一网络访问电脑 IP 的 8766 端口并加上 /?demo=1，Windows 防火墙需允许该连接。

## 通过电脑调试真实控制板

电脑的 Wi-Fi 连接 Hand-Exo 后，在 Windows 资源管理器中双击 debug_bridge.bat，保持窗口打开。电脑浏览器访问 http://127.0.0.1:8767 。该页面使用控制板的真实反馈，API 请求由电脑上的 Python 进程转发到 http://192.168.4.1 。启动代理本身不会发送运动或修改配置的命令。

代理只监听本机回环地址。Codex 可以尝试通过这个入口读取反馈、定位故障及修改已确认的配置。若设备请求失败，页面会明确报错。此入口与带有 ?demo=1 的模拟演示入口分开使用。

电脑同时需要互联网供 Codex 工作。可使用网线连接有互联网的路由器，Wi-Fi 连接控制板。只有一个 Wi-Fi 且没有其他联网方式时，可后续为固件增加 AP+STA 模式，让 ESP32 和电脑连接同一路由器。

代理自检命令为 python tests/test_debug_bridge.py，测试只访问回环模拟设备。真实硬件连通性仍需在电脑连接热点并启动代理后确认。

## 编译与上传

主程序为 ServoDriver/ServoDriver.ino，控制核心为 HandCore.h。旧版程序及修改前备份在 legacy 内。

Arduino IDE 中选择 ESP32 Dev Module，分区选择 Huge APP (3MB No OTA/1MB SPIFFS)。主程序直接包含 ServoDriver/src/SCServo 下的库副本，确保使用随项目修正的协议实现。这个副本由 tools/build_assets.py 从根目录 SCServo 同步。页面已生成到 WebAssets.h，直接编译时无需 Python，也无需另行上传文件系统。网页或根目录库更新后运行：

~~~powershell
python tools/build_assets.py --embed-only
~~~

重新提取 CAD 并打包资源需要 numpy 和上级项目中的原始 3MF、上臂项目 Three.js 文件：

~~~powershell
python tools/build_assets.py
~~~

本机 Arduino CLI 编译入口：

~~~powershell
powershell -ExecutionPolicy Bypass -File tools/build.ps1
~~~

Windows 脚本在用户临时目录的英文路径 HandExoLatestBuild 下构建，以避开 ESP32 链接器对中文输出目录的兼容问题；成功后复制固件到项目 build/firmware。tools/upload.ps1 使用同一英文暂存目录上传，默认 COM14。固件生成日志为 build/compile-latest.log。

也提供 platformio.ini，使用 ESP32 Arduino 框架和 Huge APP 分区。PlatformIO 构建尚未执行。

上传成功后连接热点 Hand-Exo，密码 handexo2026，访问 http://192.168.4.1 。热点名称和密码可在主程序顶部附近的 WiFi.softAP 调用中修改。

控制板文档 https://www.waveshare.net/wiki/Servo_Driver_with_ESP32
供电电压应同时满足控制板与 SC09 的规格。UART 使用 GPIO18 RX、GPIO19 TX，波特率 1 Mbps。
